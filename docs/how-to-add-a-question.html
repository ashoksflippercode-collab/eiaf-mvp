Adding a New Question to EIAF

A plain, non-technical guide. No programming required — there is a helper tool that does the work for you.

What is this?

EIAF answers business questions like “How much sales did I do this week?” When you want it to understand a new question, you don’t need a developer. You either run a short helper tool that asks you a few questions and sets everything up (recommended), or you edit a few simple text files by hand. This guide covers both — and how to double-check your work.

Part 1  EASIEST  Use the helper tool

This is the fastest, safest way. It writes all the settings for you and then checks them automatically.

Step 1 — Open a terminal in the project folder

On Windows: open the EIAF project folder, then open PowerShell there (or use the terminal inside VS Code).

Step 2 — Run the helper

Copy & paste this and press Enter:

.venv\Scripts\python -m backend.add_question

(If a developer set up the environment differently, they may tell you to type just python -m backend.add_question.)

Step 3 — Answer the questions

The tool asks 12 short questions. Most already show a suggested answer in [square brackets] — just press Enter to accept it. Here is what each one means:

It asks…What to type
1. The questionThe sentence a user would say, e.g. How many orders did we get today?
2. Keyword(s)The main word(s) that identify it, e.g. orders. (Used to recognise the question.)
3. Short nameA simple nickname with no spaces, e.g. orders_today. Press Enter to accept the suggestion.
4. EntityThe business thing it’s about, e.g. orders, customers, sales.
5. Database tableThe table in the database that holds this data, e.g. orders.
6. ColumnWhich column to count/add up. For a simple count, use the row id (e.g. id).
7. AggregationHow to combine the rows: COUNT (how many), SUM (total), AVG (average), MIN, MAX.
8. Date columnThe date column used to filter by time, e.g. order_date or created_at.
9. Value formatnumber (e.g. 1,234) or currency (e.g. ₹1,234).
10. Answer sentenceHow EIAF should phrase the answer. Use {value} for the number and {period} for the time, e.g. We got {value} orders {period}.
11. Time periodsWhich time ranges are allowed: today, this_week, this_month.
12. RolesWho is allowed to ask it, e.g. admin.

Step 4 — Confirm

It shows a summary and asks Write these changes? [y/N]. Type y and press Enter. It then saves everything and prints OK if all is wired correctly.

✔ That’s it. The tool just edited all the right settings for you, without touching any program code.

Worked example

Adding “How many orders did we get today?” — pressing Enter on the suggested answers and typing only a couple of values:

One thing the tool can’t do: it cannot create the database table itself. If the question uses a brand-new table (like orders), someone needs to create that table with its columns in the database. The tool reminds you which table/columns it expects.

StepSettings fileWhat it decides
1intent_patternsRecognises the question from keywords. No match → it safely says it didn’t understand (it never guesses).
2orchestrationConnects the recognised question to a business thing + a number to calculate.
3(entity file)Confirms that number and time range are allowed for this business thing.
4rolesChecks the user’s role is permitted to ask about this.
5mappingsThe only file that knows real database names. Safely reads (never deletes/changes) data.
6response_templatesTurns the number into a friendly sentence.
Why this is safe: the system can only ever read data. Even a question like “delete all records” simply isn’t recognised and is rejected — it can never reach or harm the database.

Part 3  ADVANCED  Editing by hand

The helper tool is recommended. But if you want to tweak something manually, the settings files are plain text and live in these folders:

If you want to…Edit this file
Add new wording the system should recognisebackend/config/intent_patterns.yaml
Connect a question to its databackend/config/orchestration.yaml
Allow a metric / time range for a business thingbackend/semantic/entities/<name>.yaml
Say which database table/column to readbackend/schema_registry/mappings.yaml
Set who can askbackend/config/roles.yaml
Change the answer wordingbackend/config/response_templates.yaml

These files use indentation (spaces) to show structure, and a - to mark a list item. Keep the spacing consistent with the lines around it. The one rule: a name (like a question’s short name or a metric) must be spelled identically everywhere it appears.

Part 4  Check your work & see it live

1
Check the settings are consistent. This catches typos before anything goes live and tells you exactly which file to fix: 
.venv\Scripts\python -m backend.check_config
Fix any line starting with ERROR until it says OK: N question(s) wired consistently.
2
Restart the app (settings are read once when it starts): 
.venv\Scripts\uvicorn backend.main:app --port 8080
3
Try it. Open http://127.0.0.1:8080/ in a browser and ask the new question. The coloured strip shows it flowing through all the steps; if a step turns red, it tells you which one and why.
